## 三项用户痛点如何判定

- **提醒**：第一次交办后，“继续”“别停”“记得测试”“你还没做完”这类业务催促次数必须为零。
  对应 F05/F06/F08/F12/F13。用户自愿改变需求不算提醒，但新要求必须得到保留。
- **检查**：用户不必自己运行测试、找出 Agent 漏改的文件或提醒其看失败日志。
  对应 F01/F02/F03/F04/F10/F11/F17。执行者在评测外运行独立 grader 不属于产品自测，二者都要记录。
- **收尾**：用户不必代跑回归、整理 diff、关闭本任务进程、补交付说明。
  对应 F15/F19/F20/F23/F24。未知副作用需要用户确认是安全停机，不得自动猜测已经收尾。

## 没有遗漏，但明确不扩展的事项

- 模型并非永远正确：用明确范围、独立验收与错误率揭示限制，不承诺消灭所有幻觉。
- 新的更多 MCP/Skill、向量库、跨目录个人记忆、跨平台 sandbox、scheduler/登录项、
  PC 全接管、自修改、任意并行写入均不新增。现有组合不退化，F17 只验证已经支持的边界。
- 过去已修复的敏感路径、预算穿透、目录 unknown recovery、provider mismatch 误报、
  venv symlink 缺陷不是本轮重新挂牌的未修 bug；它们是 A21/A22/A24 的回归保护。
- 随执行发现的新问题追加为 N01…，关联最近工作包及 Red；与当前目标无关的缺陷单列，
  不自行无限扩张。“无遗漏”针对本次已知清单，不表示审计找到了项目全部潜在缺陷。
