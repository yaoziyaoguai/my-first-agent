# P0–P7 实施计划

全部工作包必做，但必须按依赖逐步落地，不能一次写完所有想象中的测试再统一实现。
每个行为执行 Red→最小 Green→定向回归→记录。这里的小步是可审查检查点，不授权自动 commit。
源码导航及现有测试命令见 CODEMAP。新接口命名由执行者在既有模式中确定，先记入 RESULTS。

## P0：冻结问题、基线和真实验收方式

覆盖 F01/F24，其他包的前置。

1. 读取本包与仓库约束；核对显式 baseline 指纹、dirty 状态。漂移时阅读对应 diff，标明哪些已做，
   不强行回滚。确认已有 3502/3 和旧 K1–K5 只是历史记录，不能直接当本包通过。
2. 在新的、合成/公开授权 fixture 上建立 ACCEPTANCE 的任务 manifest 与外置 grader；
   使用现有产品 CLI/headless 入口，不建立平行模型驱动器。固定模型配置、环境、用户输入、
   评分规则、数据/工具权限、相关源码摘要和预算；在首次运行前记录摘要。
3. D01/D02/D04 为起始基线；D03/D05/D09/D10 作为不用于提示词调参的保留场景。
   grader 不能被被测产品读取或修改。执行者可以实现 grader，但不可在评分时为产品提供答案。
4. 没有真实凭据/外发/费用授权时，只实现离线 fixture、协议替身和度量记录；真实基线记 NOT RUN，
   原因记 BLOCKED，不停止安全可做的 P1–P6。不允许借旧 ledger 或使用对话里出现过的 key。
5. 若先做了离线修复才拿到预算，应从保留的授权前源码快照构建基线候选；不得 reset 主工作树。
   若无法安全重建基线，明确“无前后对比”，最终成功率仍须独立验收，不能宣称提升了多少。

交付：任务 manifest、独立 grader、记录器最小脚本/现有测试扩展；包内 RESULTS 初始化。
不建 dashboard、数据库、通用 benchmark 服务或完整 SWE-bench 平台。

## P1：正确性义务、验证与最终版本绑定

覆盖 F02/F03/F04，兼顾 F18/F21。

1. 先在 `AgentRuntime.run_turn` 公共入口复现同义测试要求差异；覆盖中文/英文、否定、引用、
   自我纠正和没有执行许可。纯 private classifier 测试只作补充，不能替代公共旅程。
2. 沿用 Goal draft、typed action、criterion admission，分离“用户要实现的行为”与“本次准许
   的副作用”。保持对引用/不可信内容的拒绝，不能仅继续堆正则或让模型自己签发权限。
3. 将批准的验证目的与准确执行证据绑定。允许在已批准的 sandbox 或 local_process 路径完成
   同一验证目的；不能为了满足名为 local_process 的义务而迫使任务退出 sandbox。
   复用各自现有 receipt，不把一种 receipt 伪装为另一种，不改变各自权限。
4. 加入最小验证输入身份与失效规则；先支持本包主要语言/测试入口。涉及文件、配置、测试
   或依赖变化时重验；无法判断影响则保守失效。不要建跨语言全能测试解析器。
5. 构造无关 exit 0、删除失败测试、skip、运行前通过但后来改坏代码等反例；完成判定必须拒绝。
6. 整理触及的重复提示和耦合，不按文件行数启动重构。文档/字符串断言不能证明模型会正确使用。

定向：A02/A03/A04/A21，已有 goal policy/verified done/process/sandbox evidence 测试。
P1 通过只证明合同正确，真实自主选择能力仍由 D01/D02/D03/D09 检验。

## P2：不用催的推进、失败修正、授权与交付

覆盖 F05/F06/F07/F08/F22/F23。

1. 用脚本化 provider 构造超过八个合法有效步骤仍未结束的任务，证明不需要 UI 反复 Resume。
   修改现有 caller budget/Runtime 策略，使任务在冻结总预算内推进；不复制 run_turn。
2. 接通任务总请求/时间上限与现有 TransportAttemptLedger；父子/压缩/协议修复都计数。
   故障请求不退款，重启不清零，预算暂停不报完成。验证非隔离和 sandbox 执行均不绕过。
3. 按 SPEC 实现有限 task-scoped consent 及撤销；默认保留严格精确模式。分别验证“无需重复
   批准同一范围”和“绝不能替用户批准新范围”，不是删掉 disclosure/approval。
4. 构造先测试失败、读日志、修正、再测试成功的旅程；有新证据才继续，无进展触发有限诊断。
   认证/额度/拒绝/未知副作用分别输出准确结果；不把所有异常都送给模型重试。
5. CLI/TUI 共用 typed action/event：可见阶段、等待时长、用户取消请求及安全边界接收新要求。
   UI 不直接改 state 或执行工具；取消 EXECUTING 不能假装工具未发生。
6. Runtime 完成前检查目标、最新验证、待办、资源和交付信息；没有可做下一步才结束，
   不以“你自己再跑一下测试”替代已授权的本地验证。

定向：A05–A08/A22/A23，limits/approval/errors/goal controls/disclosure/CLI/TUI/transport tests。
进度与取消优先可用；真实增量文本在 P3 落地，不能展示虚构模型文本。

## P3：一个真正受支持的编码模型链路

覆盖 F09，补齐 F08/F22。

1. 先核对用户当前选定模型的官方协议，记录日期、具体模型 ID、推理开关、tool-call 形状、
   token 上限、连续性字段与 streaming 完成语义。不能凭名字把 Flash 判为非推理模型，
   也不能认为打开最强档一定提高成本效率。
2. 在现有 provider/config/normalize seam 中实现明确支持的模式。若需 opaque continuity，
   先写其 immutable 载体、provider binding、恢复/压缩与禁止进入展示/Memory 的合同和测试；
   未支持的模式准确拒绝。不得静默丢字段、改模型或在 adapter 里执行工具/重试 loop。
3. 增量文本只为 advisory event；最终完整 response 才能推进 Runtime。中断/错序/残缺流不能
   凑成 tool call；断流后不得悄悄再次发送同一计费请求。解析大小、超时和秘密隔离不退化。
4. 用 MockTransport 重放正常、多工具、reasoning、上下文续接、失败和取消；真实同题 A/B
   比较只在批准预算内进行。若没有证据支持新模式，不能宣称性能提升；但仍交付准确支持矩阵。

定向：A08/A09/A22，provider/normalize/context/continuity/transport tests。
不把模型选择当作全部问题的根因；不为所有供应商实现抽象平台。

## P4：仓库探索、多文件修改和长任务工作记录

覆盖 F10/F11/F12/F13，兼顾 F18/F21。

1. 在合成项目中识别根/目录级说明、项目配置和测试入口；说明只以带来源的有界上下文输入。
   发现敏感路径拒绝时不改用 shell 偷读；普通项目路径按已授权例外读取。
2. 构造目标位于前 200 个文件之外、超过 16 个匹配的查询；返回清晰截断，模型可以缩小目录/
   关键词并继续。优先复用现有搜索/chunk/shell，不先建 LSP、AST 或向量索引。
3. 用涉及 4–8 个相关文件的变更验证读调用方、改实现/测试/说明、审查整体 diff；
   保留预置 dirty/untracked sentinel。精确文本替换够用则不新造 patch 引擎。
4. 将当前目标、用户最新修正、已改/待改文件、失败方案、有效测试与下一步放入现有 Goal/context
   工作记录；有来源/版本和预算。不得把摘要或 Memory 当授权凭证。
5. 在上下文压力、模型上下文续接、手动取消/重启情况下复测；保留最新指令，不重复已完成副作用，
   不要求用户再次描述任务。未闭合尾轮与保护事实不得被简单丢弃来压低 token。

定向：A10–A13/A21，workspace search/edit/context/compaction/goal controls tests。
先让单 Agent 做好；此包不依赖 P6 的 child 才能通过。

## P5：本地网页验收、环境诊断与资源清理

覆盖 F14/F15/F23。

1. 公网 URL policy 保持原样语义；为本任务受管开发进程定义精确 loopback origin 的独立
   显式授权。写重定向、子资源、端口替换、失效租约、非本任务服务和 LAN 的拒绝反例。
2. 在现有 process/sandbox adapter 上增加最小受管 start/observe/stop 旅程；进程身份、
   输出/时限、取消、正常退出与 unknown recovery 通过同一 effect ordering。
3. 本地功能任务先启动、读错误并诊断，再修改与浏览器验证。缺依赖的场景先生成具体问题；
   需要安装时只请求一次准确范围授权，不碰全局环境，不为方便关闭网络隔离。
4. 功能修复后通过本地真实 browser journey；关闭本任务进程/context，检查 ownership 与
   残留。取消、超时、启动后 checkpoint 失败、PID/端口复用均不能误杀用户程序。

定向：A14/A15/A23，browser URL/egress/cleanup、process group/recovery、sandbox tests。
不注册登录项，不重启其他服务，不测试真实用户登录网站。

## P6：有限扩展实用性与长期容量

覆盖 F16/F17/F20，回归 F13/F21/F22。

1. 在当前 ChildAgentRunner 上构造只读文件/搜索工具子集，复用同一个 Runtime 类；
   child 有有限多步调查能力但无写入、shell、网络、再派生能力，来源必须可由父验证。
   父子总预算共享、取消传递、错误/过期文件证据不能授权父写或宣称父完成。
2. 在合成 workspace 中分别跑 Memory 约束保持、Skill 已声明脚本、MCP 已支持传输任务。
   使用当前产品配置路径和自然输入；只有实测失败才修最近 seam，不能新增远程插件市场。
3. 补会话容量管理：先确认 existing archive 原语是否适合用户归档，不能把 compaction archive
   直接当用户会话管理。显式 preview/确认，安全归档后才能释放活跃容量；恢复需完整校验。
   使用合成历史证明 257 场景、撤销/失败/重启/损坏/满容量恢复/活动或 unknown 会话保护。
   不要求实际处理用户现有历史；不自动删除、不为此上数据库。

定向：A16/A17/A20/A21/A22，subagent/Memory/Skill/MCP/continuity tests。
P6 的多个组件可以逐个做；不得一边扩展 child 写入一边引入并行写冲突管理。

## P7：最终真实任务、独立验收与交付闭合

覆盖 F01/F18/F19/F23/F24，并核销全部问题。

1. 逐项核对 A01–A24；漏掉场景先补证，不用“总体测试绿”代替。
2. 执行 D01–D12，再执行 R01–R03。每次有独立预算/初始状态；失败先固定重现，不盲目
   重跑直到偶然过关。没有模型/浏览器/费用授权的必需项保持 BLOCKED/NOT RUN。
3. 每次修复只跑 reproducer 与 touched-area；最终源码稳定后执行一次全量、ruff、diff check。
   全量发现新问题时修复并定向验证，最终身份变化仍需最终门禁；不把已知失败藏在旧结果中。
4. 构建 non-editable wheel，在新的临时 venv 与合成 workspace 中安装运行；
   验证 import 来自安装包、无 editable/PYTHONPATH 代替、没有把 Coding Agent 辅助产物打进去。
   P0 的真实任务驱动必须能指向这个安装入口；关键真实任务在最终候选验证，代码变化按影响重验。
5. 审查 diff 的范围、安全、API/持久化兼容与资源清理；不扩大 public capability 状态。
   同步 README、架构/帮助/预算和限制，精简过时重复说明。保留原始失败、真实用量和未验证事项。
6. RESULTS 中 F01–F24 每项均有 A/D/R 证据引用；给用户一段普通语言交付，
   明确真实独立完成率、催促/代测/收尾介入次数、权限确认次数、费用和剩余限制。

最终不得以“后续请你测试”“你自己关一下进程”“你再提醒它继续”作为通过本包后的正常用法。
