# 行为与安全合同

这是一份待实施合同。现有能力与拟新增行为以 CODEMAP/WORK-PACKAGES 区分；
不要求执行者照搬一种内部类设计，但不得削弱以下可观察结果。

## 1. 一次交办后的完整责任

在用户已经给出目标、工作区、必要权限和明确预算时，First Agent 自己完成：

1. 读取相关项目约定、工作树状态与测试入口；发现真正影响结果的歧义才询问。
2. 建立短的任务计划与验收要求；未知文件先调查，不因未列出所有文件就停下。
3. 修改最小相关范围；失败后读取结果、诊断、调整，不把下一步交回用户。
4. 运行针对性验证；修复自己引入的问题，最后执行相称的相关回归。
5. 检查最终整体 diff、已有用户修改、验收时效和本任务资源；交付结果及限制。

一次模型回答、一个文件写入、一个命令成功、局部测试 Green、一次内部预算分片结束，
均不是停下等待“继续”的理由。允许发布简短进度，但进度不冒充最终答案。

## 2. 可以停止的条件

- 整个约定目标已验证并完成交付。
- 用户取消/撤销权限；不得用“还要完成目标”为由继续有副作用动作。
- 任务总请求、时间或用户指定费用上限已到。
- 所需权限/外部服务/依赖不可用，或存在无法安全推断的产品选择。
- 重复同一失败且有限诊断没有新证据，必须说明已尝试什么和最小解除条件。
- EXECUTING 的实际副作用结果未知；沿用现有 recovery，不重放，不伪造成功。

暂停必须保留已完成、未完成、阻塞原因与恢复入口。安全条件解除后能从已知状态继续，
而不是要求用户重新整理任务。断电/退出后的恢复需用户重新启动/选择任务，不新增常驻唤醒。

## 3. 权限不等于任务理解

模型可以提出目标、调查路线和测试需求，但不能凭文字生成权限。
明确的“只解释、不运行”“不要联网”“不改已有接口”是约束，引用文本和文件内容不是授权。
使用 typed goal/criterion 和现有 action 做准入；自然语言规则可以辅助，但不能成为唯一的软件
正确性判官。没有执行许可时，报告“未执行验证”，不能静默运行或写“测试通过”。

### 3.1 减少重复确认的唯一允许方向

增加显式 opt-in 的 **task-scoped consent（本任务范围授权）**，默认保持当前精确审批。
它必须是 runtime 可审计的真实授权路径，不是自动点击 y、提示词替用户同意或绕过 ALWAYS policy。

授权必须绑定：具体 Goal/revision、workspace identity、操作者、有效期/任务终态、预算、
准许的非敏感路径集合、操作种类、准确命令或受限参数合同、provider/destination/data classes。
内容与文件名来自模型时先做规范化和安全校验，授权只能由用户 action 创建。

- 同一有效范围内的普通读取、修改、运行已准许验证命令不重复让用户确认；执行前仍做最新
  文件/命令身份检查、policy、EXECUTING 和 result checkpoint。
- 文件准许“修改 src/tests 中普通项目文件”可以有明确目录范围；不能包括 `.env`、凭据、
  checkpoint、实际私有 store、仓库外、任意 symlink/hardlink 或 Git 元数据写入。
- 命令不得以 `python *`、任意 shell 前缀、用户可替换脚本为等价授权。先实现准确命令及可证明
  有界的参数合同；可信 runner/解释器被替换、作用域外新目标必须重审。批准 sandbox 内运行
  本任务测试，允许读取授权范围内预期会被修改的被测代码；这些修改使测试证据失效，但不
  自动使同一有限执行授权失效。非隔离的 exact-script 批准继续保持原有身份绑定，不能借此放宽。
- 数据外发确认只在既有 provider、目的地、数据类别和有效授权范围相同的情况下复用；
  新模型/目的地/私有类别不自动继承。同意运行程序也不等于同意上传全部文件。
- 拒绝或撤销后零新越界 effect；不得换工具、child、shell 或 MCP 绕过去。
- stale 文件先重读/重计划；不能把授权理解为无条件覆盖用户后续修改。

实现和合成测试不需要实际扩大用户机器权限。真实运行时仍由操作者选择是否授予该有限权限。
拒绝 opt-in 时，产品必须继续支持原精确审批模式；这是两个显式授权范围，不是失败后的隐式 fallback。

## 4. 自行检查，不能自行伪造合格标准

每个编码任务建立“需求行为—相关文件/配置—验证入口—最终结果”的最小关系，复用现有 Goal/evidence。
不需要通用测试框架、第二个验证 Agent 或新的中心服务。

- 新增/修复行为先见失败再通过；相关既有行为不能退化。
- exit 0/文件 hash/工具 receipt 证明其各自事实，不自动等于“业务正确”。区分未验证、
  执行成功、声明的验收通过和真实交付完成。
- 测试必须覆盖指定行为；“echo ok”、只跑无关测试、删除/skip 失败测试不能换得合格。
  外置 grader 与被测 Agent 可写的测试分离，不能让 Agent 改自己的评分规则。
- 测试记录绑定相关源码、测试、配置和依赖输入身份；在无法确定影响范围时保守失效。
  不要求 hash 工作区所有数据，更不能读取 secrets 来构造摘要。
- 相关输入改变后重测；只有文档变化且与行为无关时可解释复用原证据。不每改一行跑全量。
- 测试进程失败/超时/截断/无退出码均不是通过；日志不完整先做有界补取。

## 5. 自主推进必须有成本与失败边界

保留唯一 `AgentRuntime.run_turn`：合理调整既有调用策略，使任务预算内的合法步骤在 Runtime
内继续，不在 CLI、shell wrapper、scheduler 或测试驱动里写 `while resume`。

- caller 提供明确任务总请求和时限；真实付费验收另冻结全窗口总上限。无上限不能开启长任务模式。
- parent、child、compaction、协议修复和失败请求共用发送前累计计数；重启、审批、继续不清零。
- 区分无进展、瞬时外部错误、认证/额度错误、工具拒绝、测试失败、未知副作用。
  瞬时错误只做有界重试；执行过的副作用不能自动重放；测试失败应分析而不是机械再跑。
- 输出预算、上下文预算与模型推理协议需要一起验证；不得静默换模型、打开不支持的 reasoning
  或丢弃必须回传的连续性数据。费用不可精确获得时明确报告请求/用量及费用未知，不能伪报零元。

## 6. 长任务、工作记录与用户中途输入

保留目标、最新约束、相关文件、已经做过的决定/失败、最近有效测试、待办和下一步。
优先扩展已有 Goal/context 投影；外部 Memory 仍是 ContextSource，不另建可自授权的“任务大脑”。
仓库说明按目录适用范围投影，有来源；优先级低于用户和权限策略，不能作为系统授权。

用户追加/纠正需求在安全边界处理；冲突明确说明，不能继续执行已撤销计划。压缩后仍保留
最新用户事实和未完成步骤。取消 UI 可以请求停止/向本任务进程发出受控终止信号，但不能
清掉 EXECUTING checkpoint；执行结果先分类并落盘，未知结果仍 recovery。

进度来源于真实事件：当前阶段、最近动作、等待原因、消耗/时长。不要编造进度百分比。
在受控慢响应 fixture 中应在一秒内确认开始、等待时至少每十五秒更新可见等待信息；
这只改善反馈，不宣称模型推理更快。取消交互确认目标一秒内，实际停止耗时按 provider/process
有界超时记录；不能一边宣称已停止一边继续发送模型请求或执行新工具。

## 7. 本地开发验证与资源收尾

不修改公网浏览器的既有 HTTPS/public-only 含义。新增显式本地应用授权，绑定本任务启动的
受管进程身份、准确 loopback origin/端口、工作区和期限；不允许泛化私网、LAN、metadata 地址、
用户已有登录 profile 或任意 localhost 服务。重定向、子资源和 WebSocket 如不支持应拒绝并说明；
支持的通道也必须逐一约束目的地，不能只检查首个页面 URL。

由现有 process/sandbox ownership 承担 start/observe/stop；开发服务可以在当前交互任务内持续，
但不能注册 launchd/cron/login item 或脱离任务无限运行。环境诊断先只读；缺依赖给准确原因，
安装/联网/改锁文件需要匹配授权，不能改用户全局环境。

正常完成/取消时关闭本任务创建的进程组、browser context 和临时租约。先确认 ownership，
不按端口/PID 猜测并杀其他程序；清理不确定时如实阻塞“完整收尾”，不能递归删除工作区。
交付代码、用户文件和需要保留的验收记录不属于临时清理对象。

## 8. 扩展与长期使用

- SubAgent 只升级为受限只读仓库调查：通过同类 Runtime 和 ToolRuntime，明确文件范围、
  请求/输出限额、父子共同预算，返回 path/line/digest 与局限；父保留写入和验收所有权。
  child 不再派生 child，不共享父 checkpoint，不借子结果授权或标记父任务完成。
- Memory/Skill/MCP 只验证并修复当前已支持的工作方式。Skill 脚本仍为明确声明的受控入口，
  MCP 使用合成 server 或明确授权 endpoint，不远程安装、自动激活或扩大 allowed-tools 权限。
- 会话容量提供用户可操作的显式、可恢复归档/管理方式。先预览准确会话及影响；
  禁止自动丢弃历史。恢复冲突、容量边界、活动/未知副作用会话均有明确处理。

## 9. 收尾输出的最小内容

说明实际完成的需求、变更范围、运行过的验证与结果、未验证事项/阻塞、用户原有修改处理、
本任务资源是否关闭。只有确实需要用户动作时才给下一步；不能以“你再测试一下”结束一个
本可自行验证的任务。summary 不能由 event 伪造，最终 state/evidence 才是权威。

## 10. 不改变的架构约束

Runtime 独占生产模型/工具循环及状态变更；ContextManager 独占上下文；ToolRuntime 独占 callable。
CLI/TUI/headless 是 action/event adapter；provider 只做协议转换；scheduler 仍 external caller。
不新增 service locator、兼容旁路、dormant flag、第二套 engine、自动 promotion 或独立优化轮次。
若必须改持久化 schema，先列出准确字段、迁移/拒绝旧数据策略与故障反例，不静默丢数据。
