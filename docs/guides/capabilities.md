# First Agent：现在能做什么

更新于 2026-10-23（含 consent-ux 轮）。当前适合定位为 **macOS、单用户、工作区内的 CLI 个人试用版**。
代码里有下列能力，不等于每项都在当前安装物上完成了真实模型验收。
正式声明仍以 [CURRENT_CAPABILITY_STATUS](../architecture/CURRENT_CAPABILITY_STATUS.md) 为准，
各能力保持 `implemented-candidate`；当前测试、安装身份和未决项见
[RESULTS](../handoffs/2026-10-11-product-reliability-closure/RESULTS.md)。

## 日常入口与核心能力

| 能力 | 你可以怎样用 | 重要边界 |
| --- | --- | --- |
| 自然语言交流 | 问代码、解释文件、讨论方案、给出多步任务 | 简单回答不强行创建 Goal；能力仍取决于模型和可用上下文 |
| 工作区阅读与检索 | 列目录、查路径、全文搜索、分段读文件，按来源定位代码 | 相对路径、no-follow、敏感路径拒绝和读取限额；不是全盘扫描 |
| 修改代码和文档 | 创建目录、写入/编辑文件，结合已有测试迭代 | 写入须审批；命名文件有有限语法的完成下界，不是任意自然语言的完备解释器 |
| 结构化本机命令 | 用 `local_process` 执行精确 executable、argv、cwd，例如运行项目测试 | **同一用户权限，不是沙箱**；有精确批准、租约、截止时间和输出限制。不要批准不理解的命令 |
| 原生沙箱命令 | 用 `sandbox_exec` 在 macOS Seatbelt 下做只读验证或工作区写入 | 默认 workspace-write、network off；也存在需精确披露/批准的 danger-full-access 与 network full。后者不应当成隔离执行。无 Docker 依赖，不可用时不静默降级 |
| 受治理 Shell | `shell_exec` 执行经审批的 `/bin/sh -c` 精确命令字符串 | 支持 shell 语法，不是禁止所有脚本；任何模式 network off，有时限与输出上限。danger-full-access 不隔离文件系统；没有任意后台/TTY/sudo 的产品保证 |
| 多步任务推进 | 模型读文件、提工具调用、执行、检查，持续到终态或明确边界 | 同一 Runtime 循环；审批、额度、超时、未知效果或真实阻塞会停下来，不是无限自治 |
| 中途纠正 | 在安全输入边界补充/改变要求，撤销尚未执行的旧调用 | 旧证据绑定随版本更新失效；不等于能抢占所有运行中的系统调用，也不能保证模型理解无误 |
| 暂停、恢复和新任务 | `/pause`、`/resume`、`/cancel`、`/new`；重启同一 workspace/state 继续 | 有 durable checkpoint；未知效果要先人工分类，不自动重做已可能发生的副作用 |
| 上下文管理 | 在预算内保留当前目标、审批、纠正和相关材料；压力下压缩旧内容 | 有界上下文，不是无限记忆；压缩内容不能授予权限或替代真实证据 |
| 自身历史 | 检索当前工作区 First Agent 的历史；归档/恢复已终结会话 | 不是搜索 Codex、Claude 或整个电脑的私人会话；不持续监控本机活动 |
| 来源与证据 | 文件/工具/Web 来源回执、Sources 视图、完成证据核对 | 证明观察与执行的来源及绑定，不证明语义必然正确；不把普通模型“done”当权威终态 |
| 安全审批 | 精确预览、拒绝、撤销；文件审批处可选 `f`（同文件复用，16 次/60 分钟）或 `d`（已声明目录复用），等价于既有 `/approve-goal-target|directory`；也可 `y` 只批本笔 | 不是 allow-all；复用授权随任务变化/关闭结束，`/revoke-goal-target` 可撤销；文件工具的路径保护不能被误当成所有本机进程的 OS 级隔离 |
| 外发许可（consent） | 远端模型首次发送时可选 `s`（本会话常规对话数据）或 `r`（常规对话数据＋**已验证的工作区读取**：活跃任务下 read/list/search 的文件摘录、目录清单、搜索结果，含任务内新建文件），32 次发送/60 分钟；额度与到期会反馈；`/revoke-provider-consent` 随时撤销，撤销或到期后重新询问 | `r` 只覆盖 proof-backed 读来源（绑定任务与内容摘要）；写/编辑文件结果的稳定来源在许可内静默复用（与读取 proof 同一绑定语义）；**命令输出与无活跃任务的对话内读取仍逐次披露**（2026-10-23 旧行为「读/验证类全部逐次、小任务 16 次」已被 P5 取代，历史数据见当日记录） |
| 费用和运行限制 | 可配置共享 model-attempt ledger，父子任务与重启共用累计请求上限 | 请求计数不是精确账单；远端已接收的请求不保证能撤销或退款 |
| CLI / headless | 安装物 `first-agent` 启动，用相同 typed action 与状态机 | 当前推荐 CLI；不是已发布的桌面 App、Web SaaS 或跨平台产品 |

## 需要显式配置的可选能力

这些能力不是本轮 base 安装默认开启的功能，不能因为有对应代码就声称开箱即用。

| 能力 | 已实现的范围 | 不承诺的范围 |
| --- | --- | --- |
| 公开 Web | 配置 Tavily 后，逐次批准 Search/Extract，返回来源回执 | 不等于任意网页登录；需要自己的服务配置与额度 |
| 浏览器 | 可选 `browser` extra + `--browser`；专属 Chromium、受限站点交互、人工接管、隔离下载；也能检查本任务受管本地页面 | 不接管日常 Chrome，不操作整个桌面，不保证任意网站/登录/支付。当前 D06 真实模型闭环未验收 |
| Owner preference | 从当前用户原话确认偏好，纠正、停止未来召回 | 项目/Web/模型内容不能自行变成跨项目偏好；forget 不撤回已发送的远端副本 |
| Memory | 显式本地 store，跨会话 remember/search/get/update/forget，经批准写入并绑定工作区和 profile | 本地明文、词法召回；不是向量语义库、无限记忆、跨设备云同步 |
| Skill | 显式可信本地目录，按需读 body/reference；manifest 声明的 owner-local Python entrypoint 可经批准在固定身份、network-off 沙箱中执行 | 不支持任意 scripts 自动执行、远程自动安装/激活、借 allowed-tools 扩权；执行路径仍是候选能力 |
| MCP | 显式可信 stdio catalog，descriptor 校验，逐调用审批、超时、safety latch 与未知结果处理 | 不保证任意 MCP server/远程 transport 都兼容；崩溃后的未清 latch 需人工处理 |
| SubAgent | 受审批的有界只读调查；子进程复用同一 Runtime，最多 6 次模型调用、8 次只读工具调用 | 无写入/递归派生/自由并发协作；不继承父历史、Memory、Skill 或 MCP。返回建议，不替父侧验收 |
| TUI | 可选 Textual 终端界面，共用 Runtime，有来源、回看、多行编辑 | **实验性**；恢复后的某种外发确认尚有显示缺口，不作为当前日用入口 |

## Scheduler 的真实状态

有 portable 调度控制面和独立 macOS host 实现，但当前 wheel 的 `first-agent-schedule`
**未装配可运行的 host composition**。直接调用管理/调度入口会返回
`needs_019_config / host_profile_unavailable`，不能把它宣传成可直接使用的定时任务。

普通 CLI 不安装 macOS 登录项。cold wake 需要单独显式启用和批准；本次收尾没有更改登录项、
后台服务或系统调度。Linux、Windows、云端 host 也没有当前 qualification。

## 目前最重要的不足

1. **证据通过不等于业务做对。** 历史真实样本中，模型把“同时提供两个参数就拒绝”做成了
   “两个值不同时才拒绝”，但产品仍到达 typed 完成。当前增加了逐项正负边界检查指引、
   明确的用户验收边界与 `FAIL_FALSE_COMPLETION` 报告；它们不是通用语义正确性证明。
   新安装物的普通编码样本已真实通过，但纠正/恢复样本受累计请求预算限制暂停，
   零改写样本未运行；不能把普通样本通过当成历史纠正失败已经闭合。
2. **交互仍偏工程工具。** 审批和外发确认仍需要用户参与；复杂任务应拆出可验证结果，
   不能把“请一直做完”理解为它可以跨过权限或额度边界。
3. **可选能力没有全部变成成熟产品入口。** Scheduler 不能开箱即用、TUI 有已知缺口，
   浏览器/第三方集成的覆盖也有限；不应按代码目录数来计算成熟能力数。
4. **项目环境仍需要你准备。** Agent 自身能启动不代表该项目的 pytest 等依赖可用。
   先激活项目环境、确认命令能在当前终端运行，再启动 Agent；本轮真实测试曾因启动
   PATH 缺少测试环境而正确 blocked，补齐测试环境后才完整通过。

因此，它不是“只有聊天的壳”，已经能执行真实的文件、命令和有界多步工作；
也不是可以不看结果、交给它任意任务的通用员工。

## 建议先试的三类工作

- 在项目副本里改一个明确功能，并跑你已有的独立测试，再查看 diff。
- 根据工作区材料整理说明、比较实现或定位问题，要求给文件与行号来源。
- 做一个两步任务，中途纠正、暂停再恢复，检查是否遵循你的最新要求。

启动方式见 [日用指南](daily-use.md)。不建议第一天就交付生产部署、真实支付、重要数据迁移，
或无独立验收的大型代码重写；本轮没有增加这些保证。
